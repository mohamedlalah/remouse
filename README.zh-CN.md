# Remouse

**把遥控器方向键变成可自由移动的光标。**

[English](README.md)

一个 Android TV 无障碍服务，用真正的光标取代焦点导航 —— 方向键控制光标在屏幕上自由移动，OK 键点击。给那些本来就不是为电视做的界面用：网页、装到电视上的手机应用、藏在方向键够不到的地方的设置项。

## 为什么要做这个

电视界面靠焦点在元素之间跳。一旦某个应用没有焦点顺序 —— 网页、手机版应用、带进度条的播放器 —— 就彻底卡住。

光标能解决，但最直觉的实现方式行不通：**注入触摸手势在多数电视应用上是没用的**。它们围绕焦点导航设计，根本不处理触摸事件。在 TCL 桌面上模拟一次点击，只会把焦点复位到第一个卡片，应用不会打开。

Remouse 改走无障碍节点：找到光标下的节点，直接对它调用 `ACTION_CLICK`，只有在光标下确实没有可点节点时才回退到手势注入。就是这一个差别，让它真正能用。

## 功能

- **自由光标** —— 方向键 8 方向移动，按下即以低速起步，按得越久越快。短按一下只走 10 像素左右，小按钮照样够得到。
- **节点点击** —— 对无障碍节点执行 `ACTION_CLICK`，不是注入触摸。手势注入会静默失败的地方它能点得动。
- **就近吸附** —— 光标不必精确压在按钮上，屏幕宽度 5% 以内的可点元素都算；多个元素重叠时取最里层最具体的那个。
- **悬停高亮** —— 中性描边框标出即将点击的元素，按 OK 之前就能确认，不用猜。
- **滚动模式** —— 长按 OK 切换，方向键翻光标底下那个列表。
- **边缘翻页** —— 光标顶住屏幕边缘 300 毫秒，底下的容器就往那个方向翻页。
- **暂停而不用关服务** —— 长按返回键把所有按键交还系统，对付光标反而碍事的界面；再长按一次恢复。
- **空闲淡出** —— 停手 3 秒光标消失，下一次按键立刻回来。

指针本身刻意做得很安静：深色半透明填充加一圈白描边，不发光、不做动画。一暗一明两层保证它在亮背景和暗背景上都看得见。

## 按键

| 按键 | 光标模式 | 滚动模式 |
| --- | --- | --- |
| 方向键 | 移动光标（短按微调，按住加速） | 翻光标底下的列表 |
| OK | 点击高亮框标出的元素 | 点击 |
| 长按 OK | 切到滚动模式 | 切回光标模式 |
| 长按返回键 | 暂停 / 恢复 Remouse | 暂停 / 恢复 |
| 短按返回键 | 正常返回 | 正常返回 |
| 音量 +/− | 光标速度 | 滚动速度 |
| 光标顶住屏幕边缘 | 往那个方向翻页 | — |

## 安装

自己编译（见下）或从 [Releases](../../releases) 下载 APK，装好后启用无障碍服务：

```
设置 → 无障碍 → Remouse → 开启
```

国产电视会把这些步骤大部分挡住。装不上、或者无障碍开关打开后又自己关掉，看 **[docs/install-on-tcl.md](docs/install-on-tcl.md)** —— 里面写了 TCL / 雷鸟机型怎么连上 ADB，以及必须先清掉的三道厂商限制。

## 编译

```bash
git clone https://github.com/zy0816/remouse.git
cd remouse
./gradlew assembleRelease
```

产物在 `app/build/outputs/apk/release/`。

关于签名：项目根目录有 `platform.keystore` 时 release 构建会用它（作者用 AOSP 平台密钥签名，方便在特定电视上原地覆盖升级）；没有则自动退回默认的 debug 签名，照样能编译。仓库里不含任何密钥。

环境要求：Android 7.0（API 24）以上，编译 SDK 为 API 33。

## 实现要点

整个程序就是一个 `AccessibilityService`：

- `flagRequestFilterKeyEvents` 配合 `canRequestFilterKeyEvents`，让 `onKeyEvent` 在前台应用之前拦到遥控器按键。**两个都要写** —— 只写运行时 flag 的话不会报错，但回调永远不来。
- 光标和高亮框是两个 `TYPE_ACCESSIBILITY_OVERLAY` 窗口，因此不需要悬浮窗权限。
- 命中判定从最高层的窗口往下遍历，先用光标周围一个小方框剪掉 bounds 不相交的整棵子树，再取包含光标的最小节点；没有就取吸附半径内最近的那个。
- 所有节点操作（`getWindows()`、遍历、`performAction`）都跑在专门的 `HandlerThread` 上。这些是跨进程调用，放主线程会直接卡在正在绘制光标的那一帧上。
